# CLAUDE.md

Guidance for Claude Code (claude.ai/code) in this repository.

## Purpose and direction

The goal is a bot that makes money on Polymarket by finding markets where careful, price-blind research of public information disagrees with the market price, then betting small, Kelly-sized amounts on that disagreement. The current stage is **paper trading to collect evidence**: is the research calibrated (Brier score), and how much should we trust it versus the market (λ)? Live money comes only after the ledger shows it.

Principles, which should hold for any future change:
- **LLMs judge, code decides.** Models only read text and estimate probabilities. Gating, sizing, caps, tax, execution and maths are deterministic Hub code, so decisions are reproducible and testable. Agents that used to decide (Evaluator, Re-Evaluator, Executioner) were removed for this reason.
- **Price-blind research.** No model ever sees the market price `q`. Models given `q` anchor on it. Trust in the market is applied in code (the λ-shrink), where it can be measured.
- **Assume the market is usually right.** Cheap filters run before expensive research. Large disagreements are probable misreads, not big edges. Sizing is conservative: ¼-Kelly, shrink toward `q`, minimum edge, exposure caps.
- **Measure everything, learn slowly.** Every decision, including skips and rejects, goes to the decision ledger and is scored on resolution. `stats.md` reports Brier, calibration, P&L and a λ fit. The Overseer nudges a few bounded knobs, only with enough new resolutions, is auto-reverted if Brier worsens, and never touches sizing.
- **Measure before you filter.** A new filter starts as measurement: a shadow run, a triage shadow, or a record-only score. Hard-reject only extreme cases until resolved data justifies more.
- **Cost-aware.** LLM calls and evidence fetches are the main cost: per-tick budgets, caches, a quick stage before the full one.
- **Humans approve, code acts.** Approval flags put a human yes/no between a decision and money or knob changes. The Discord bot only relays Hub files and records votes: it never decides, filters or keeps preferences.
- **Fail safe, never silently.** Content errors mark the single market `inactive` and the loop moves on. Infra errors are retried. Unknown config values raise instead of falling back. Trades are never retried blindly. Measure-only runs never flag the real market; they ledger `shadow_failed` or an error field instead.

## Why each phase looks the way it does

1. **Ingest: direct Gamma/CLOB APIs.** The old scraper plus SQLite was a stale second copy. The public APIs give fresh prices, real order books and a YES/NO token mapping by label, never by position.
2. **Gate and triage: cheap before expensive, and wary of traps.**
   - A deterministic score prefers quiet markets (less attention, more mispricing) that resolve soon enough to score. Failing markets back off and retire.
   - One cheap price-blind triage call asks whether public research can plausibly beat this market at all (a coin flip or insider-driven question cannot). The answer does not change, so it is cached.
   - The tension: quiet markets have the most mispricing, but they are also where one actor can cheaply set a trap. So triage rates `manipulation_risk`, and the gate and an integrity check look for thin-volume moves, concentrated holders or wallets, wide spreads, rewritten rules and past disputes.
   - Measure before filtering: only extreme integrity cases reject, the rest is a record-only score, and triage rejects are sampled into a shadow run.
3. **Research: two stages, question-led, skip on doubt.**
   - The quick stage (model knowledge only) drops markets where we already agree with the price; a shadow run checks this does not discard edge.
   - The FULL stage asks the right questions before searching (`crux_v1`): the review of past researches showed question failures (nobody asked what all recent polls show; no reference class) and stale evidence. A scout maps the landscape, an architect writes 5-8 role-assigned questions (mechanism, comparator, evidence, horizon, skeptic; code enforces the required roles), each is searched, one capped gap round fixes unanswered ones, and an audit checks that a line's fact is really in its page.
   - Two judges (P(YES) and P(NO), same rules) replace three samples that shared evidence and so agreed by construction; code flips J2 and averages. A wide framing gap means unsure, so skip. A huge gap to `q` is likelier a misread than an edge, so skip too.
   - The evidence source is A/B tested because A-IQ is expensive and unproven.
4. **Execution: deterministic sizing.** λ-shrink trusts our estimate only partly until the ledger fit says otherwise. An edge at the midpoint is not real, so size is capped at real ask depth. Paper mode loosens λ/edge only to collect scored bets faster. With `CONCIERGE_APPROVAL=1` a passing trade is parked as an offer and executed only on a yes vote, after re-quote and re-size; the edge must still clear.
5. **Resolution and post-mortem: classify why.** Every ledger market is resolved, including skipped and rejected ones, so filter costs are measurable. The post-mortem separates fixable process errors from variance. Open tags catch new failure modes, trusted only once they recur.
6. **Overseer: bounded, evidence-gated learning.** LLM self-tuning overfits noise, so it acts only after enough new resolutions, moves few knobs in small steps within hard bounds, and auto-reverts on worse Brier. With `CONCIERGE_APPROVE_DIRECTIVES=1` each knob change waits for a yes vote instead.

Open questions the project is working toward:
- Is research Brier better than the market's? What is the fitted λ?
- Is A-IQ worth its cost versus web search?
- Do the skip thresholds (spread, misread gap) throw away good bets?
- Does the quick filter discard edge? (quick-stage shadow)
- What do triage rejects cost? (triage shadow)
- Does the question-led pipeline beat the old one? (rubric review `scripts/review_research.py`, backtest `scripts/backtest.py`, Brier by directive version)
- Do integrity/manipulation flags predict a less accurate market price?

## Architecture

Hub + LLM agents trading pipeline. Specs in `docs/01_architecture.md` to `docs/06_concierge.md` (pipeline, sizing math, skill and agent I/O, concierge); keep them in sync with behavior.

**Hub (`orchestrator/`)** is the only component that spawns agents or touches disk. `loop.run_forever` runs `run_pipeline_tick` every `PIPELINE_INTERVAL_SEC` and the Overseer every `OVERSEER_INTERVAL_SEC`. `orchestrator/phases/` has one module per phase or stage (`p1_ingest`, `p2_routing`, `p3_quick`/`p3_full`/`p3_evidence`/`p3_queue`, `p4_execution`, `p5_resolution`, `p6_overseer`). Phase helpers: `p2_integrity` (integrity features, signal coverage), `p3_research` (the crux pipeline: scout, architect, per-crux search, gap round, audit, J1/J2 judges, `backtest_research`), `p3_samples` (judge aggregation: J2 flip, union range), `p4_approval` (offers, inbox votes); `common`, `agent_call` and `research_state` are shared. `orchestrator/util.py` holds small coercion helpers. `runner_stubs.py` holds the deterministic stub responses for `stub` / `stub_error`. Tests must patch the defining submodule, not the package.

1. **Ingest.** Gamma API via `polymarket_api.py` (wrapped by `scraper.py`): open binary Yes/No markets in the days window with enough liquidity. Ingest pages (up to `MAX_PAGES`) until `PMBOT_INGEST_LIMIT` rows pass `gate.eligibility` evaluated on the Gamma row (price band, spread, etc.; no extra API calls); skipped rows are only logged by reason, not ledgered. `market_id` = condition id (`0x...`).
2. **Gate + triage + integrity.** `gate.py` (eligibility, score, backoff, arbitrage) scores markets (recorded only, no relevance cut); every eligible market goes to the price-blind `triage` agent (cached per market/event forever) and every researchable one gets `passed: true` and its `end_date` in `01_Filters/`. `PMBOT_GATE_BUDGET` / `PMBOT_TRIAGE_BUDGET` default 0 = unlimited (>0 is an emergency cap). Paid research stays capped in Phase 3 (quick 8, FULL 3), queue order is soonest resolution first; holder/integrity fetches run concurrently.
   - `status: retired`: triage rejects, triage `manipulation_risk: high`, 6 consecutive gate fails (`MAX_FAILS`).
   - Gate rejects `suspicious_move`, `concentrated`, `wide_spread` (fixed `MANIP`). Missing signals never reject. Holders: data-api `/v2/holders`, in-budget markets only, before triage. Basis: share of outstanding shares from `/v2/oi` (`holder_basis: supply`, top-1 0.25 / top-3 0.50), else share of top-20 holders (`top_n`, 0.50 / 0.75, record-only: `concentrated` rejects only on supply).
   - Integrity (`market_integrity.py`, in-budget, before triage): `integ_*` features over 1d/7d/30d from CLOB prices-history, data-api `/v2/trades`, CLOB book, Gamma. Hard rejects `ramp_thin`, `wallet_dominated`, `rules_changed`, `disputed_before` (fixed `INTEGRITY`); `integ_score` (0-1) and `integ_flags` are record-only, copied to later ledger rows.
   - Triage shadow: stable ~10% of triage rejects (`TRIAGE_SHADOW_RATE`, max 2/tick, last in Phase 3) get a measure-only quick estimate, ledger `triage_shadow`; no trade or status change.
   - Per tick a `signal_coverage` row (`market_id` `_tick`) counts missing gate signals; above `SIGNAL_COVERAGE_ALERT_FRAC` (0.5) it logs an error.
3. **Price-blind research.** QUICK (one `deep_researcher` call in `mode: quick`, no A-IQ, `PMBOT_QUICK_RESEARCH_BUDGET`) → `q` inside `[p_low, p_high]`, range width <= 0.20 (`research_max_quick_width`) and quick confidence not `low` → ledger `research_skip no_divergence`, else FULL (`PMBOT_FULL_RESEARCH_BUDGET`, parallel via `PMBOT_RESEARCH_WORKERS`): the crux pipeline (`p3_research`): `scout` (one broad pull → landscape) → `briefer` as architect (5-8 cruxes, roles enforced in code) → parallel per-crux search (≤ `RESEARCH_MAX_WEB_CALLS` 12) → `gap_analyzer` (one round, ≤ 3 follow-ups, then an assess-only re-assessment of followed-up cruxes; `source: rules` cruxes are not searched) → source-quality tags (yaml > persisted `source_classifier` cache `00_System/source_quality_cache.json` > heuristics; one batched cheap call per research for unknown domains) + `auditor` (≤ 10 lines vs page text; Gemini lines `unverified`) → `deep_researcher` judges (`mode: judge`) on a trimmed bundle (answered/contradicted cruxes top `JUDGE_LINES_PER_CRUX` 4 lines each, unanswered ones ≤ 2 partial lines): arm `two` = J1 asks P(YES) + J2 asks P(NO) in parallel, arm `one` = one judge with a hash-picked framing (`JUDGE_ARM_MODE` `ab|one|two`, default `ab`; cost and Brier by `judge_arm` in `stats.md`) → code flips J2, `p` = mean, range = union, `spread` = framing gap → `02_Active_Research/`. `RESEARCH_DEPTH` is `lite` (4-5 cruxes, no audit) when the potential max order is below `DEPTH_FULL_MIN_USD`, else `full`.
   - Skips (`research_skip`): `no_evidence` (no usable evidence rows after the web retry/fallback; no judge call), compound market (`orchestrator/compound.py`: architect flags AND/OR, judge gives component probabilities and a correlation, code combines and compares with the stated p) gap > `research_max_sample_spread` (`compound_inconsistent`), framing gap (J1 vs flipped J2) > `research_max_sample_spread` 0.15 (`sample_disagreement`; the knob's meaning changed, so the directives version was bumped once with `research_pipeline: crux_v1`) or `|p - q|` > 0.40 (knob defaults; gap wider in paper mode), `thin_evidence_disagreement` (an `evidence` crux still unanswered after reassess and `|p - q|` > `research_thin_evidence_max_gap` 0.15, a `FILTERS` default that is not an Overseer knob). Non-English markets (scout `locale`) get one local-language query per evidence/comparator/horizon crux (Brave `country`/`search_lang`, extractor translates to English; cap raised by `RESEARCH_LOCAL_EXTRA_WEB_CALLS` 6; fields `locale_country`, `locale_language`, `local_queries`). The queue defers FULL beyond `MAX_FULL_PER_EVENT_PER_TICK` 1 per event and `MAX_FULL_PER_COUNTRY_PER_TICK` 2 per triage country; each market has its own crux plan and bundle (never a sibling's copy); Phase 4 skips with `event_sibling_guard` when a recent sibling ended `probable_misread`/`thin_evidence_disagreement` or researched p of a neg-risk event sums above 1.15. Refresh after a TTL or 8-point price move; `PMBOT_RESEARCH_TICK_BUDGET_SEC` caps tick time.
   - Evidence: `PMBOT_EVIDENCE_SOURCE` `aiq|web|ab` (default `ab`: stable per-market A/B). A-IQ failure falls back to `web_searcher`; the Hub sanitizes odds lines. 24h query caches. `stats.md` splits Brier by `evidence_source`. The web arm's backend is `PMBOT_WEB_BACKEND` `brave|gemini` (default brave if `BRAVE_API_KEY` set and live): Brave Search + page fetch + `web_extractor` (`orchestrator/brave_search.py`; Brave gets `keyword_query(question)`, no "as of" clause or question words, the extractor gets the full question; a kept=0 result logs `[WEB-DIAG]` per page: host, fetched vs snippet-only, chars, first 80 chars), falling back to the gemini `web_searcher`, which runs one query per call in parallel. Bundle lines get `[E<n> | <age>d]` / `undated` / `STALE` labels when rendered for `deep_researcher` (`evidence.label_bundle`; stored data unchanged); in judge mode the label adds the source-quality tag (`config/source_quality.yaml`) and `unverified`.
   - Quick shadow: stable ~10% of quick `no_divergence` skips (`SHADOW_RATE`, max `SHADOW_MAX_PER_TICK` 2, only after the FULL budget) also run FULL: no report, state change or trade. Ledger `shadow_research`; `stats.md` 'Shadow: quick vs full vs market'. Errors ledger `shadow_failed`.
   - Helper-role failures degrade, never flag: scout fails → architect uses the rules alone; architect fails → template cruxes; gap analyzer or auditor fails → skipped and flagged; one judge fails → the other is used; both fail → the market is flagged inactive. Pipeline fields (`pipeline`, `research_depth`, `cruxes_total`, `crux_answered|unanswered|contradicted|rules`, `gap_queries`, `audit_dropped`, `audit_unverified`, `framing_gap`, `source_mix`, `pipeline_flags`, `web_calls`, `judge_arm`, `judge_framing`, `compound_*`, `discounted_sources`) go to the research frontmatter, research state and ledger rows. Offer evidence (`evidence_bull`/`evidence_bear`) is the verbatim lines a judge cited (audit-verified ones; a side with none verified falls back to cited lines marked `(unverified)`). Judges report a `prior` (+ `prior_kind` reference_class|structural|judgment; `base_rate` only from real counts with `base_rate_n`/`base_rate_source`; ledger fields `prior`, `prior_kind`, `base_rate`, `base_rate_n`; `stats.md` 'Prior kinds') and move from it only on answered cruxes; an unanswered comparator crux always gets a history follow-up query first(unanswered ones widen the range, never pull toward 0.5) and discount interested/unproven party forecasts; every quick result is logged as `[QUICK] ...`; `orchestrator/playbooks.py` is an empty registry for future category playbooks.
4. **Execution** (Hub code, no agent): `compute_allocation` (`skills/calculate-trade-allocation`): λ-shrink toward `q`, ¼-Kelly. `PAPER_TRADE_MODE` uses `PAPER_LAMBDA`/`PAPER_MIN_EDGE` (0.5/0.03) via `effective_lambda()`/`effective_min_edge()`; live `LAMBDA`/`MIN_EDGE` (0.3/0.04). Tax is annual offset only: 25% of NET annual gains; Kelly is pre-tax. Real CLOB asks, order capped by ask depth within 2c (failed quote skips the tick) → `execute_polymarket_trade` → `03_Trades/` + ledger `traded`/`below_edge` (idempotent intent files). Approval mode adds `offer_pending` → `offer_approved` / `offer_stale` / `offer_declined` / `offer_expired` (+ `user_vote`); `stats.md` 'Offers & votes'. Ledger rows carry `runner_backend`. Research rows also carry `provider` and `model` (from `config/models.yaml`). `stats.md` has 'Brier by model', 'Brier by provider' and 'Brier by runner backend'.
5. **Resolution** (Gamma `closed` + `outcomePrices`, also for gate-rejected ledger markets) → `04_Post_Mortems/`; `failure_class` (`bad_info|bad_reasoning|resolution_misread|variance|correct`), ledger `post_mortem`. Open tags `new:<slug>` (+ `failure_tag_definition`) are counted in `00_System/failure_tags.json`, established at `FAILURE_TAG_MIN_COUNT` (3). Payload adds `crux_table`, `known_unknowns`, `cited_evidence`, `researched_at`, `resolved_at`, `end_date`; `bad_info` only when a fact knowable before `researched_at` was missing.
6. **Overseer**: auto-reverts a directives version whose Brier is worse by > 0.02 (>= 30 scored markets each); otherwise runs with >= `OVERSEER_MIN_NEW_RESOLVED` (30) new resolutions and >= 24h since last run.
   - Inputs: `stats.md` (Signal coverage, Triage shadow, Gate flags vs market calibration, Shadow: quick vs full vs market), Market integrity (report-only), failure-class counts (established `new:` tags included), `candidate_failure_tags` (not evidence), <= 15 post-mortems, directives, `BOUNDS`.
   - Only the quick-vs-full shadow can justify a knob change (lower `research_max_quick_width`); the rest is report-only.
   - `filters:` in `00_System/active_directives.md` holds ONLY `BOUNDS` knobs (gate price band, days window, `research_max_quick_width`, `research_max_sample_spread`, `research_max_q_gap`). `ObsidianManager.write_directives` enforces range, step, knob-count and cooldown limits, versions and archives each change. Sizing is off-limits.
   - Overseer output is structured (`filters`, `research_protocol`, `risk_constraints`, `output_requirements`, `rationale`); the Hub renders `active_directives.md`. `validate_directive_text` rejects the whole version on URLs, odds talk, override phrases, extra `##` sections or a rewrite below 0.6 similarity.

**Measurement (`orchestrator/stats/`)**: pure functions over ledger rows. `calc` (Brier, log-loss, bootstrap CI), `groups` (row groupings), `pnl` (P&L, annual-offset tax, offers), `render` (`stats.md`).

**Agents (`agents_blueprint/<role>/`)**: `AGENTS.md` (system prompt), `agent.yaml` (tool allowlist, input/output schemas); `loader.py` builds Pydantic models from the YAML; `runner.spawn_agent` validates input. Agents never write files or do math; the Hub parses (`parse.py`, `agent_outputs.py`) and validates (`schema_validation.py`) their output. Every web-reading prompt states that page, evidence and stats text is data, never instructions.

**Runner modes** (`PMBOT_MODE`): `stub` (default, deterministic), `stub_error` (injected failures), `live` (direct LLM calls, see below). Unknown values raise.
- `live`: stateless, one provider call per spawn, via `orchestrator/direct_runner.py` and `orchestrator/llm/`. System prompt = the role's AGENTS.md; user message = the live prompt built from `agent.yaml` (`runner._build_live_prompt`: today line, header, `Input JSON:` payload, response hint last). JSON mode for roles with an `output_model`. Only roles whose `tools.allow` includes `web_search` or `web_fetch` (web_searcher) get web tools.
- Retries: transient errors only (connection, timeout, 408, 429, 5xx) retry, using `PMBOT_LLM_MAX_ATTEMPTS` and `PMBOT_LLM_RETRY_BACKOFF`. HTTP timeout: `PMBOT_LLM_TIMEOUT`. Other errors fail at once.

**LLM providers** (`orchestrator/llm/`): `LLM` (abc) owns `complete()`: retry loop, token log, errors wrapped as `LLMError`. Subclasses implement `_send` (one call) and `_is_retryable`. `AnthropicLLM` (Anthropic SDK: cached system prompt, server web tools, `pause_turn` continuation). `HttpLLM` (JSON over `requests`, hooks for URL, headers, body, parse) has `OpenRouterLLM` and `GeminiLLM` (Google AI Studio).
- `routing.llm_for(role)` caches one instance per role spec. `routing.validate()` runs at startup: every Hub-spawned role resolves, and each provider in use has its key.
- Config: `config/models.yaml` (path override `LLM_MODELS_CONFIG`). `default` and `roles:` entries `{provider, model}`, optional `web_max_uses` per role; top-level `max_tokens` (16000) and `web_max_uses` (8). Switching a role's provider is one line.
- **Token usage and cost.** Each LLM call appends one row to `Vault/05_Ledger/llm_usage.jsonl` (`orchestrator/llm/usage.py`: tokens, `thinking_tokens` (the thinking part, already included in `output_tokens`), `batch` flag, `cost_usd`). `config/prices.yaml` is user-maintained with no shipped prices: a model without a price gets `cost_usd: null` and stats say `price missing`. `batch_discount` (0.5) applies to batch calls. `stats.md` 'LLM cost' (`orchestrator/stats/cost.py`) shows cost per day, role, model and market, and Brier per dollar.
- **Web evidence filter.** `web_searcher` must output `- <fact> | <url> | <date>` lines extracted from pages it retrieved, or `NOT_FOUND`. `orchestrator/web_filter.py` (called from `evidence.fetch_web_rows`) drops lines with no URL, or whose URL is not among the provider's retrieved citations (`LLMResponse.citations`, via `direct_runner.last_citations()`; Gemini also contributes grounding-chunk title domains, since its URIs are opaque redirect links). A real web call with no citations at all (`None`) is unverifiable: all lines dropped, counted as `dropped_unverifiable`. Every path has a named counter (`not_found` = the extractor answered NOT_FOUND, not a guard drop; `dropped_blank`); the `[WEB-GUARD]` log prints them all. Junk-key model output (`{": ": null, ...}`) raises a schema error and is re-asked with `format_validation_error` (also in `run_structured_agent` and the web extractor call). Below-edge trade/ledger records carry the edge-sign side (null when q is inside the range), not the skill's tie-break YES. Counts go to `Vault/05_Ledger/web_filter.jsonl`, and `stats.md` has a 'Web evidence filter' section with the drop rate by model. Per-role `temperature` / `reasoning` live in `models.yaml`; quick-mode calls (`payload.mode == "quick"`) always use the lowest thinking level (`direct_runner._reasoning_for`).
- Precedence per role: `LLM_ROLE_<ROLE>=provider:model` env, then YAML `roles`, then `LLM_DEFAULT=provider:model` env, then YAML `default`. Example: `LLM_ROLE_TRIAGE=openrouter:<model-id>`.
- Keys: `ANTHROPIC_API_KEY` (anthropic), `OPENROUTER_API_KEY` (openrouter; optional `OPENROUTER_BASE_URL`, `OPENROUTER_HTTP_REFERER`, `OPENROUTER_APP_TITLE`, `OPENROUTER_PROVIDER_IGNORE` comma list, default `Alibaba`, sent as `provider.ignore`; a 403 "inappropriate content" is retried once), `GEMINI_API_KEY` (gemini). An unknown provider or role, or a missing key, raises at startup.
- Add a provider: one subclass (`LLM`, or `HttpLLM` for JSON APIs) with `provider_name`, `api_key_env` and its hooks, plus one entry in `orchestrator/llm/registry.py`. Model ids go in config, never guessed.
- **Batch API (opt-in).** Per-role `batch: true` in `config/models.yaml` (default false) sends latency-insensitive calls, triage and triage-shadow quick estimates, through Anthropic Message Batches, Gemini `batchGenerateContent` or OpenRouter `/batches` via `LLM.complete_many` (~50% cheaper, minutes of latency). Web calls stay synchronous. OpenRouter has no cancel endpoint, so a timed-out batch is abandoned (may still be billed). `PMBOT_LLM_BATCH_POLL_SEC` (30) and `PMBOT_LLM_BATCH_MAX_WAIT_SEC` (1200) bound the wait. Timeout, failure or submit error → cancel → sync fallback for unfinished items. See `orchestrator/llm/base.py` and `routing.py`.

**Hub outbox and Discord bot.** `orchestrator/notify.py` writes `06_Concierge/outbox/`: offers built from the Phase 4 trade record, a daily digest, and directive proposals (approval on). Votes in `06_Concierge/inbox/` are read by `p4_approval.process_inbox` and `p6_overseer.process_directive_votes`, polled every `CONCIERGE_POLL_SEC` between ticks when a flag is on. The **Discord bot** (`orchestrator/discord_bot.py`, a separate process run with `python3 -m orchestrator.discord_bot`, never imported by the Hub) is the only front-end. It posts outbox files, records button votes, and answers owner questions read-only from `stats.md`, `02_Active_Research` and the ledger. Its model is the `concierge` role in `config/models.yaml`; `agents_blueprint/concierge/` (`hub_spawned: false`, so startup validation skips it) holds its Q&A prompt. Env: `DISCORD_BOT_TOKEN`, `DISCORD_CHANNEL_ID`, `DISCORD_OWNER_ID` (required); `CONCIERGE_TZ`, `CONCIERGE_QUIET_HOURS`, `CONCIERGE_POLL_SEC` (optional). Setup: `docs/06_concierge.md` section 5. Notification never raises and never breaks a tick.

**Vault I/O (`obsidian_utils/` package)** is the single gatekeeper for writes: `manager.py` (`ObsidianManager`) validates through `schemas.py` (Pydantic payload models, atomic writers); `research_bundle.py` and `directives.py` are its mixins. Vault root: `PMBOT_VAULT_PATH`, else repo root; dirs `Vault/00_System` … `Vault/04_Post_Mortems`, `Vault/06_Concierge` (`VAULT_PATHS`; `outbox/` Hub→user, `inbox/` user→Hub, `_done/`, `_pending/`, `_posted.json`). Tests use a tmp dir.

**Error model: in-place state machine, no error directory.** On an agent, parse or validation error the Hub sets `status: inactive` and `error_log` on that market's own artifact and moves on. Inactive markets are skipped until `orchestrator.replay` clears the flags. Infra failures are retried, content failures mark inactive, soft gate failures back off (`next_check_at`), a failed trade call is not retried. Keep these separate.

**Config.** Strategy constants are in `config/trading_constants.py`: `F_MAX`, `LIQ_FRAC`, `FILTERS`, `PAPER_TRADE_MODE`, A-IQ settings, `RESEARCH_*` thresholds, and the Overseer `BOUNDS` (the only Overseer-tunable knobs). These groups are fixed, not Overseer knobs: `MANIP`, `INTEGRITY`, `SHADOW_*`, `TRIAGE_SHADOW_*`, the crux-pipeline limits (`RESEARCH_MAX_WEB_CALLS`, `MAX_GAP_ROUNDS`, `GAP_MAX_QUERIES`, `AUDIT_MAX_LINES`, `CRUX_COUNT`, `DEPTH_FULL_MIN_USD`), `SIGNAL_COVERAGE_ALERT_FRAC`, `FAILURE_TAG_MIN_COUNT`, `DIRECTIVE_TEXT_*`. Env tunables (`PMBOT_*`, `OVERSEER_MIN_NEW_RESOLVED`: timeouts, retries, budgets, workers) are in `orchestrator/config.py`. Concierge env: `CONCIERGE_APPROVAL` (0; 1 = offers need a yes vote), `CONCIERGE_APPROVE_DIRECTIVES` (0; 1 = Overseer changes need a yes vote), `CONCIERGE_POLL_SEC` (300), `CONCIERGE_OFFER_TTL_SEC` (14400), `CONCIERGE_DIRECTIVE_TTL_SEC` (172800), `DISCORD_WEBHOOK_URL` (optional push; failures logged, never raised). LLM env: see LLM providers. Discord bot env: see Hub outbox and Discord bot.

## Deploy

`deploy/` runs the stack on AWS Lightsail (Ubuntu 24.04) as systemd units: `pmbot-hub` (Hub, `main.py`), `pmbot-bot` (Discord bot), and `pmbot-backup` with its timer (daily Vault backup, 14 kept). `deploy/setup.sh` is idempotent. The server env file is `/etc/pmbot/pmbot.env` (mode 600), built from `deploy/pmbot.env.example`; secrets live only there. Install, verify and operate steps: `deploy/README.md`.

## Testing notes

- `tests/orchestrator/conftest.py` has autouse fakes so phase tests never touch the network: `polymarket_api.executable_quote` (asks follow the row under test; `QUOTE_HINTS` for direct Phase 4 rows), `fetch_holder_concentration` (returns None), the three integrity fetchers `fetch_price_history`, `fetch_trades`, `fetch_book` (return None), and the evidence source (`PMBOT_EVIDENCE_SOURCE=aiq`); `BRAVE_API_KEY` and `PMBOT_WEB_BACKEND` are cleared so no test reaches Brave. Tests that need real behavior override them.
- `test_polymarket_api.py` fakes HTTP with fixtures in `tests/orchestrator/fixtures/polymarket/`; skill tests use `tests/skills/fixtures/`.

## Knowledge graph (graphify)

`graphify-out/` holds a code knowledge graph. For codebase questions, run `graphify query "<question>"` first (`graphify path "<A>" "<B>"` for relationships, `graphify explain "<concept>"` for one concept) before broad grepping; `graphify-out/GRAPH_REPORT.md` only for wide reviews. After changing code, run `graphify update .` (AST-only, no API cost).
